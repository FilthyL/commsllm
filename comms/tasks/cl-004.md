## Goal
Keep the derived labels in sync with the last COMMS header. Dispatch headless runners when a runner is set to `action`. Ping stalled lanes and escalate to the owner. Keep a live task board in the bus PR's description.

## Acceptance criteria
- [x] `comms-router.yml` runs on `issue_comment: created`, `pull_request_review: submitted` and `pull_request_review_comment: created`. It skips immediately if the actor isn't in `trusted_actors`, or if `paused: true`.
- [x] `scripts/router.py` (stdlib, importing `scripts/comms.py`) turns a parsed header into a list of actions, as a pure function with unit tests. The workflow then applies them with `gh`:
      - set exactly one `next:*` label and one `state:*` label, using this mapping: task→building, ready/fixed→review, review+changes→changes, review+approve→approved, blocked→blocked, done→remove both;
      - `next=owner` → add `needs:owner` and assign `owner`;
      - `to=codex` with `codex_runner: action` → `gh workflow run codex-agent.yml -f pr=<n>`; `to=claude` with `claude_runner: action` → `gh workflow run claude-agent.yml -f pr=<n>`. If the target workflow doesn't exist yet, log and continue;
      - a native Codex review (author `chatgpt-codex-connector[bot]`, no header) is mapped per PROTOCOL §7.7.
- [x] `comms-watchdog.yml` runs on `schedule: */15 * * * *` and `workflow_dispatch`. For each open PR whose title starts with `[cl-`/`[cx-`: find the last header. If the `next` actor has had no comment, push or reaction for `sla_minutes`, post `type=ping` with the wake mechanism (PROTOCOL §2.1). After `max_pings` consecutive unanswered pings, post `type=blocked from=router to=owner next=owner`, add `needs:owner`, and assign the owner.
- [x] The watchdog rewrites the bus PR body with `python3 scripts/comms.py board` plus a table of open task PRs (PR, task, next, last activity age).
- [x] All untrusted strings reach scripts through `env:` or files, never via `${{ }}` inside `run:`.
- [x] Unit tests cover the mapping table, the pause and untrusted-actor skips, ping counting, and escalation.

## Assumptions
- Shared owner-login comments/pushes/reactions count as recipient activity; semantic COMMS senders disambiguate comments.
- Push activity uses GitHub's repository activity timestamps, including force pushes. Headerless Codex thumbs-up is synchronized by the watchdog because reactions have no router event.
- Unmapped message types preserve state labels. Watchdog pings are spaced by the SLA and escalate after two unanswered pings at the default configuration.
- Shellcheck is unavailable. The sandbox blocks live `gh api` calls; adapter behavior is unit-tested. TRANSPORTS T5/T6 remain the Lead's after-merge checks.
