## Goal
Let both agents run with no live session, so the system survives the Claude session ending and doesn't depend on Codex cloud honouring bot mentions. The switch is `claude_runner` / `codex_runner` in config.

## Acceptance criteria
- [ ] `claude-agent.yml` uses `anthropics/claude-code-action@v1`. Triggers: `workflow_dispatch` (input `pr`), plus `issue_comment` and `pull_request_review` containing `@claude`. Auth is `claude_code_oauth_token: ${{ secrets.CLAUDE_CODE_OAUTH_TOKEN }}`, falling back to `anthropic_api_key`. `allowed_bots: "chatgpt-codex-connector[bot]"`. The prompt tells it to act as the Lead per `CLAUDE.md` on PR `<n>`. A first step reads `claude_runner` from config and exits early unless it is `action`. Permissions are only `contents: write`, `pull-requests: write`, `issues: write`.
- [ ] `codex-agent.yml` uses `openai/codex-action@v1`, triggered by `workflow_dispatch` (input `pr`). It checks out the PR head branch, runs with `permission-profile: ":workspace"` and the prompt "Act as the Builder per AGENTS.md on PR <n>; the last COMMS/1 header is your instruction", and writes the final message to a file. A second job pushes any commits to the PR branch and posts the final message as a comment. Then it dispatches `ci.yml` on the branch with `gh workflow run ci.yml --ref <branch>`, because pushes made with GITHUB_TOKEN don't trigger `pull_request` CI.
- [ ] Both workflows no-op cleanly (exit 0 with a log line) when their secret is missing.
- [ ] `docs/RUNNERS.md` gives the owner checklist: which secrets to add and where (`CLAUDE_CODE_OAUTH_TOKEN` from `claude setup-token`, or `ANTHROPIC_API_KEY`; `OPENAI_API_KEY`), how to flip the runners in config, and the cost notes.
- [ ] Passes actionlint via `scripts/ci.sh`.
